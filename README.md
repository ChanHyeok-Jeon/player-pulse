# player-pulse · 유저 동향 아침 브리핑

> 매시간 공개 커뮤니티 글을 모으고, 정해진 요일·시각에 **중요도 순 유저 동향을 Slack 전체 채널로** 보냅니다.
> 중요도는 **코드가 근거와 함께 계산**하고, AI는 비슷한 글을 묶기만 합니다.

| | |
|---|---|
| **기간** | 2026.10 |
| **성격** | 개인 프로젝트 (개발 PM 업무 자동화) |
| **데모** | https://chanhyeok-pm.cloud/pulse/ |

<br>

## 왜 만들었나

게임사 사업PM 인턴 때 커뮤니티 동향 파악 과제에 **약 2시간**이 걸렸고, 현업 담당자도 매일 아침 **20~30분**을 들여 정리해 공유한다고 들었습니다.
출시 후 모니터링에서 커뮤니티 반응을 매일 확인하는 일을 자동화해, PM은 **판단과 전달**에 시간을 쓰도록 하는 것이 목표입니다. 리포트 한 건을 만드는 데 걸리는 시간은 실제 실행에서 **약 6~16초**였습니다.

## 구조

```
[매시간 수집]  디시인사이드 이터널 리턴 마이너 갤러리 목록 · 스팀 커뮤니티 리뷰(한국어·영어)
               robots.txt가 허용한 공개 목록만, 작성자 정보 없이 제목·조회·댓글·추천·시각만 저장, 최근 7일만 보관
    ↓
[AI: 묶기]   Amazon Bedrock (Nova Pro) · "주제 | 부서 | 감정 | 글 번호들" 한 줄 형식으로 반환
    ↓
[코드: 검증·집계]  없는 글 번호 제거 · 글 하나는 한 주제에만 · 잡담·밈·대상이 불분명한 주제 제외
                  글 수 · 조회 · 댓글 · 추천 · 심각 키워드 글 · 부정 반응 · 스팀 비추천 → 점수 → 중요도 5단계
    ↓
[Slack]  ●●●●● 긴급 · ●●●●○ 높음 · ●●●○○ 보통 · ●●○○○ 낮음 · ●○○○○ 참고 + 근거 + 원문 링크
         부서 태그(밸런스 · 클라이언트·서버 · 매칭·랭크 · 운영·제재 · 콘텐츠·이벤트 · BM·상점 · UX)로 각 부서가 자기 주제를 바로 찾음
```

## 발송 규칙

- 기본: **월~금 09:00** (웹에서 시각·요일 변경 가능)
- 기간: 직전 발송 시각 ~ 이번 발송 시각. **월요일은 금요일 09:00 ~ 월요일 09:00 주말 동향**
- **기간을 직접 정해 동향 받기**: 웹에서 시작~끝을 고르면 그 기간 리포트를 바로 만듦 (Slack 발송은 관리자만)

## 중요도 계산

```
점수 = 글 수×1 + 반응(조회/50 + 댓글×2 + 추천×3)×0.15 + 심각 키워드 글×2
       + 부정 주제면 글 수×1.5 + 스팀 비추천×1.5
같은 기간 주제끼리 점수 순위로 상위 10% ●●●●●, 30% ●●●●○, 60% ●●●○○, 85% ●●○○○, 나머지 ●○○○○
긍정 동향은 ●●○○○까지만
```
심각 키워드: 튕김·크래시·접속 불가·서버·렉·핑·버그·핵·결제·환불·매칭·로딩·롤백·계정·정지 등

## 만들면서 고친 것

| 문제 | 해결 |
|---|---|
| 1위가 특정 개인에 대한 잡담 | 개인·잡담·밈 주제를 제외하도록 규칙 추가 + 코드에서 한 번 더 거름 |
| "특정 버그 불만"처럼 막연한 주제 | 대상 이름을 꼭 넣게 하고, 막연한 표현이면 코드가 제외 |
| 같은 글이 여러 주제에 중복 집계 | 글 하나는 한 주제에만 세도록 코드에서 막음 |
| 글이 많으면 AI가 도구 호출(JSON) 형식을 깨뜨림 | 짧은 순번 + 한 줄 텍스트 형식으로 바꾸고 코드가 파싱 |
